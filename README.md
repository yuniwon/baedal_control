# Delivery Menu Sync

Windows 로컬 PC에서 배민, 요기요, 쿠팡이츠, 땡겨요, 배달특급, 네이버주문의 메뉴·가격·옵션을 한 곳에서 수집하고 반영 준비까지 할 수 있는 Electron 기반 데스크톱 앱입니다.

상세 진행 현황과 현재 구현 상태는 [docs/current-status.md](docs/current-status.md)를 기준으로 확인합니다.
플랫폼별 메뉴·가격·옵션·이미지·상태·프로모션 제약은 [docs/platform-capability-matrix.md](docs/platform-capability-matrix.md)와 [구조화 JSON](docs/platform-capability-matrix.json)에서 확인합니다.
통합 메뉴 원본, 예외 판단, 플랫폼 확장, 세션 복구, 외부 백업의 상위 결정은 [기반 설계](docs/superpowers/specs/2026-07-25-canonical-catalog-platform-foundation-design.md)에 기록되어 있습니다. 실행 계획은 [초기 통합 메뉴·예외 처리](docs/superpowers/plans/2026-07-25-canonical-catalog-onboarding.md), [플랫폼 플러그인·세션](docs/superpowers/plans/2026-07-25-platform-plugin-session-orchestration.md), [백업·복원·출력](docs/superpowers/plans/2026-07-25-catalog-backup-export.md), [안전한 다중 플랫폼 반영](docs/superpowers/plans/2026-07-25-safe-multiplatform-write.md) 순서로 진행합니다.

## 통합 메뉴 시작 방식

새 데이터베이스는 `collecting` 상태로 시작합니다. 이때 플랫폼 가져오기는 메뉴·옵션 원본과 수집 이력만 저장하며 `menus` 또는 매핑을 자동 생성하지 않습니다.

1. 연결되고 최신 메뉴 수집이 완전한 플랫폼 중 하나를 초기 기준으로 선택하거나, 빈 통합 메뉴로 시작합니다.
2. 기준 플랫폼에서 만든 초안의 메뉴명·가격을 확인하고 각 원본을 `포함` 또는 `무시`로 결정합니다.
3. 다른 플랫폼에서 이름이 안전하게 일치하는 연결 후보만 확인합니다. 애매하거나 남는 원본은 검수 항목으로 보냅니다.
4. 결정 요약을 확인해 통합 메뉴 버전 1을 활성화합니다. 이 과정은 어떤 배달 플랫폼에도 쓰기 요청을 보내지 않습니다.
5. 활성화 이후의 가져오기는 기존 원본 ID 연결만 갱신합니다. 새 원본, 플랫폼별 누락, 가격 차이, 중복 옵션은 통합 메뉴를 몰래 바꾸지 않고 검수함에 남깁니다.

기존 버전에서 이미 `menus` 데이터가 있던 데이터베이스는 마이그레이션 시 `legacy / active / version 1`로 보존되어 새 온보딩 화면으로 강제 이동하지 않습니다. 메뉴가 없던 새 데이터베이스만 `collecting / version 0`으로 시작합니다.

## 플랫폼 처음 연결

1. `메뉴 가져오기` 화면에서 `로그인 창 열기`를 누릅니다. 네이버주문처럼 기존 브라우저 로그인을 재사용할 플랫폼은 빈 계정으로도 세션을 열 수 있습니다.
2. 앱은 먼저 기존 전용 Chrome 또는 최근 확장 세션을 확인합니다. 확인된 세션이 없을 때만 `로그인 열기`로 이동합니다.
3. 추가 인증이나 매장 선택이 나오면 전용 Chrome에서 한 번만 완료하고 `로그인 완료 확인`을 누릅니다. 이 확인은 비밀번호를 다시 제출하지 않습니다.
4. 상태가 `연결됨`이 된 뒤 `메뉴 불러오기`를 누릅니다. 이미 불러온 플랫폼은 `변경사항 다시 확인`으로 표시됩니다. 세션이 만료됐거나 추가 인증 중이면 메뉴 수집은 시작되지 않습니다.
5. 플랫폼이 보고한 전체 개수와 실제 수집 개수가 다르면 가져오기는 `일부 실패`로 끝나며 기존 카탈로그는 바꾸지 않습니다.

### 쿠팡이츠 처음 연결

1. 쿠팡이츠 아이디와 비밀번호는 앱에 입력하거나 저장하지 않습니다. `쿠팡이츠 로그인 열기`로 실제 Google Chrome의 고정 전용 프로필을 엽니다.
2. 최초 한 번은 사용자가 직접 로그인하고 Chrome 비밀번호 관리자에 로그인 정보를 저장합니다.
3. 설정의 `쿠팡이츠 로그인 버튼 1회 자동 클릭 허용`을 명시적으로 켭니다. 기본값은 꺼짐입니다.
4. 세션 만료 후 `다시 읽기`를 누르면 앱은 입력값 자체가 아니라 두 입력칸이 Chrome에 의해 채워졌는지만 확인하고 로그인 버튼을 정확히 한 번 누릅니다.
5. `/merchant/management` URL과 로그인된 관리 화면 표식이 함께 확인된 경우에만 같은 요청에서 메뉴 수집을 계속합니다.
6. 로그인 오류, CAPTCHA, OTP, 계정 선택, Chrome 비밀번호 관리자 또는 Windows 잠금 해제 요구, 확인 시간 초과가 나타나면 자동화를 중단합니다. 자동 재시도하지 않으므로 Chrome에서 직접 해결한 뒤 `인증 완료 확인`을 누릅니다.

초기 기준 플랫폼은 매장마다 선택할 수 있습니다. 초기 설정이 끝나면 통합 메뉴가 기준이 되고, 나머지 플랫폼의 신규·누락·가격 차이와 옵션 연결 차이는 검토 대상으로 표시됩니다. 현재 온보딩과 검수 결정은 읽기·로컬 기록만 수행하며 플랫폼 쓰기는 실행하지 않습니다.

## 개발 실행

```bash
npm install --ignore-scripts
npm run setup:electron
npm run dev
```

`--ignore-scripts`로 설치했기 때문에 처음 한 번은 Electron 바이너리를 별도로 받아야 합니다. `npm run setup:electron`을 실행하면 자동으로 내려받습니다.

```bash
npm run build
```

## 저장 위치

- SQLite: Electron `userData` 경로의 `delivery-menu-sync.db`
- 일반 플랫폼 계정 정보: Electron `userData` 경로의 `credentials.json` (쿠팡이츠 제외)
- 계정 정보는 Electron `safeStorage`로 암호화된 문자열로 저장
- 쿠팡이츠 로그인 정보: 실제 Google Chrome 고정 전용 프로필의 Chrome 비밀번호 관리자가 소유하며 앱 DB·IPC·로그에 저장하지 않음
- 개발 실행과 직접 Electron 실행도 모두 같은 `delivery-menu-sync` 경로를 사용하도록 고정

## 현재 주의사항

- 신규 플랫폼 API 필드와 메뉴 관리 URL은 운영 계정으로 첫 캡처 후 전용 규칙을 한 번 더 검증해야 합니다.
- 메뉴 추가/수정/실행 기록 흐름은 로컬에서 동작하도록 연결되어 있습니다.
- 원본 메뉴/옵션이 2회 연속 누락되면 `플랫폼에 없음`으로 확정되며, 이 상태는 미리보기 실행 대상에서 제외됩니다.
- 메뉴와 옵션 기본 화면에서는 내부 ID를 숨기고 운영자에게 필요한 상태 정보만 먼저 보여줍니다.
- 실제 자동 로그인 후 메뉴 수정은 사이트 구조 변경 시 셀렉터 보정이 필요할 수 있습니다.
- 같은 자격증명이 거절된 뒤에는 자동으로 다시 제출하지 않습니다. 로그인 정보를 수정하거나 열린 인증 화면에서 직접 해결해야 합니다.
- 쿠팡이츠의 자동 클릭 동의와 1회 클릭 잠금은 로컬 DB에 저장되지만 아이디·비밀번호나 그 파생값은 저장하지 않습니다.
- 2026-07-26 전용 프로필 재시작 점검에서는 네이버주문을 제외한 5개 플랫폼 모두 로그인 화면으로 돌아와 `세션 만료`로 판정됐습니다.
