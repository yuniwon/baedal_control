# Six-Platform Catalog Ingestion Design

- 작성일: 2026-07-21
- 대상 플랫폼: 배달의민족, 요기요, 쿠팡이츠, 땡겨요, 배달특급, 네이버주문
- 기준 플랫폼: 배달의민족

## 목표

가게 운영자가 지원 플랫폼별로 매번 로그인하고 화면을 검수하지 않아도, 각 관리화면에서 메뉴·가격·옵션·연결 상태를 빠짐없이 가져와 로컬 원본과 정규화 카탈로그로 보관한다. 플랫폼별 인증 특성은 존중하되 수집 완료 판정은 동일한 수준으로 엄격하게 적용한다.

## 핵심 원칙

1. 로그인 방식은 플랫폼별로 최적화한다.
2. 이미 유효한 브라우저 세션이 있으면 계정 재입력보다 세션 재사용을 우선한다.
3. 자동 로그인이 허용되는 배민·땡겨요·요기요·배달특급은 저장 계정 로그인을 우선 지원한다.
4. 자동화 로그인을 차단하거나 추가 인증을 요구하는 쿠팡·네이버는 관리 브라우저 세션을 재사용한다.
5. 목록 API가 일부만 반환하면 상세 API 또는 메뉴별 상세 화면을 순회한다.
6. 플랫폼이 알려준 전체 개수와 실제 수집 개수가 맞지 않으면 성공 처리하지 않는다.
7. 부분 수집 결과로 기존의 정상 카탈로그를 덮어쓰지 않는다.
8. 배민은 메뉴 구성과 가격의 레퍼런스지만 다른 플랫폼 원본은 변경하지 않고 차이만 계산한다.

## 플랫폼별 인증 전략

### 배달의민족

- 현재 Playwright 계정 로그인 흐름을 유지한다.
- 유효 세션 재사용을 우선하고 세션이 없을 때 저장 계정으로 로그인한다.
- 메뉴·옵션 페이지의 페이지네이션 완료 여부를 검증한다.

### 요기요

- One ID 일반 로그인 폼을 Playwright로 자동 입력한다.
- 로그인 성공 후 브라우저 컨텍스트를 유지한다.
- 로그인 정책 또는 추가 인증이 바뀌면 관리 브라우저 세션으로 폴백한다.

### 쿠팡이츠

- 자동화 브라우저의 로그인 API 403을 정상적인 플랫폼 제약으로 취급한다.
- 전용 Chrome 프로필의 기존 로그인 세션을 우선 사용한다.
- `all-menu-dishes`와 `all-options?fetchDish=true` 원본을 저장하되 `mappingDishCount`와 실제 `mappingDishes` 길이가 다르면 상세 수집을 추가 수행한다.

### 땡겨요

- 현재 저장 계정 자동 로그인을 유지한다.
- WebSquare 데이터 컬렉션과 상세 편집 화면을 이용해 가격 변형을 읽는다.
- 화면의 모든 버튼 문구를 상태로 오인하지 않도록 실제 데이터 필드에서 노출·품절 상태를 읽는다.
- 옵션 그룹과 메뉴 연결을 별도 수집한다.

### 배달특급

- 공식 사이트가 연결하는 PAYCO 스마트오더 사장님 사이트의 일반 로그인 폼을 사용한다.
- 인증 후 네트워크 응답을 우선 수집하고 부족한 필드는 상세 화면에서 보완한다.
- 배달특급 매장만 선택됐는지 매장 식별자를 검증한다.

### 네이버주문

- 스마트플레이스 로그인 세션을 우선 재사용한다.
- 계정 로그인 자동화를 먼저 시도하되 보안 확인이 발생하면 QR·일회용 번호·수동 인증을 허용한다.
- 인증 완료 후 동일 전용 프로필을 재사용하여 이후 실행은 입력 없이 진행한다.
- 스마트플레이스의 예약·주문 대상 매장과 메뉴 관리 화면을 명시적으로 확인한다.

## 수집 계층

```text
플랫폼 인증
  -> 매장 선택 확인
  -> 목록 API 원본 캡처
  -> 상세 API/화면 보강
  -> 플랫폼별 파서
  -> 완전성 검증
  -> 원본 스냅샷 저장
  -> 정규화 메뉴·옵션 저장
  -> 배민 기준 차이 계산
```

### 원본 스냅샷

각 수집 실행은 다음 증거를 보존한다.

- 페이지 URL과 종류
- 캡처 시각
- 메뉴·옵션 API 요청 URL과 응답 본문
- 화면에서 보완한 구조화 항목
- 플랫폼이 보고한 전체 항목 수
- 실제 정규화 항목 수
- 수집 경로와 폴백 이력

### 정규화 데이터

- 메뉴 ID, 이름, 카테고리, 설명, 이미지
- 기본가와 플랫폼별 가격 행
- 판매·노출·품절 상태
- 옵션 그룹 ID, 이름, 필수 여부, 최소·최대 선택 수
- 옵션 항목 ID, 이름, 추가금, 상태
- 메뉴와 옵션 그룹의 전체 연결 목록

## 완전성 계약

플랫폼 어댑터는 단순 배열 대신 다음 결과를 반환한다.

```ts
interface PlatformMenuFetchResult {
  menus: PlatformMenuSnapshot[]
  optionGroups?: PlatformOptionGroupSnapshot[]
  completeness: {
    menuCatalog: 'complete' | 'incomplete' | 'unknown'
    optionCatalog: 'complete' | 'incomplete' | 'unknown'
    optionBindings: 'complete' | 'incomplete' | 'unknown'
    expectedMenuCount?: number
    collectedMenuCount: number
    expectedOptionGroupCount?: number
    collectedOptionGroupCount: number
    issues: string[]
  }
  fetchMode: 'embedded_browser' | 'managed_browser' | 'api_capture' | 'dom_fallback'
}
```

다음 조건에서는 import run을 `partial_failed`로 남긴다.

- 알려진 메뉴 개수보다 적게 수집됨
- 알려진 옵션 그룹 개수보다 적게 수집됨
- `mappingMenusCount`보다 실제 연결 메뉴가 적음
- 로그인됐지만 대상 매장을 확인하지 못함
- API 응답이 잘렸거나 파싱할 수 없음
- DOM 폴백만으로 전체 항목임을 증명할 수 없음

## 실패와 재시도

1. 저장된 세션 확인
2. 허용된 플랫폼은 저장 계정 자동 로그인
3. 내부 API 수집
4. 상세 API 또는 항목별 상세 화면 순회
5. 관리 브라우저 폴백
6. 추가 인증이 필요한 경우에만 사용자에게 표시

각 단계는 구조화된 실패 코드를 남기며, 실패한 수집은 기존 정상 데이터를 absent로 바꾸지 않는다.

## 보안

- 계정 정보는 Electron `safeStorage`로 암호화한다.
- 쿠키와 세션은 플랫폼별 전용 브라우저 프로필 안에 둔다.
- API 인증 토큰을 로그나 UI에 출력하지 않는다.
- 캡처 응답을 저장하기 전에 인증 헤더와 개인정보 필드를 제거한다.

## UI

설정 화면에 6개 플랫폼을 표시하고 플랫폼마다 다음 상태를 제공한다.

- 계정 저장 여부
- 세션 연결 여부
- 마지막 정상 수집 시각
- 메뉴·옵션·연결 완전성
- 자동 로그인, 관리 브라우저 열기, 다시 수집
- 추가 인증 필요 여부

## 검증 기준

- 6개 플랫폼이 앱 계약과 설정 화면에 존재한다.
- 배민·땡겨요는 기존 자동 로그인이 회귀하지 않는다.
- 쿠팡은 세션 재사용 후 메뉴와 옵션 원본을 자동 수집한다.
- 요기요·배달특급은 일반 로그인 폼 자동화가 가능하다.
- 네이버는 자동 로그인 또는 최초 인증 후 세션 재사용이 가능하다.
- 수집 불완전 상태를 정상 완료로 표시하지 않는다.
- 같은 원본을 다시 가져와도 중복 메뉴·옵션이 생성되지 않는다.
