# 배달 플랫폼 기능·제약 매트릭스

- 기준일: 2026-07-25 (KST)
- 대상: 배달의민족, 요기요, 쿠팡이츠, 땡겨요, 배달특급(PAYCO 스마트오더), 네이버 주문
- 목적: 하나의 기준 메뉴를 플랫폼별로 가져오고, 비교하고, 안전하게 전파하기 위한 제품·자동화 계약
- 구조화 원본: [`platform-capability-matrix.json`](./platform-capability-matrix.json)

## 1. 결론

여섯 플랫폼을 하나의 가장 작은 공통분모로 하향 평준화하면 안 된다. 기준 메뉴는 모든 정보를 보존하고, 플랫폼별 어댑터가 `정확히 표현`, `결정적으로 변환`, `정보 손실`, `수동 처리`, `미확인` 중 하나를 판정해야 한다.

특히 가격은 하나의 숫자가 아니다.

```text
기준 메뉴
├─ 가격 variant: 기본 / M / L / 1~2인 / 3~4인 ...
│  └─ 채널 가격: 배달 / 포장·픽업 / 매장식사
├─ 옵션 그룹: 필수 여부 / 최소·최대 선택 / 수량 / 옵션 가격
├─ 이미지: 원본 / 파생본 / 플랫폼별 승인 상태
├─ 판매 상태: 판매 / 당일 품절 / 숨김 / 채널별 숨김 / 예약 노출
└─ 프로모션: 쿠폰 / 리뷰 이벤트 / 할인랭킹 / 스탬프
```

현재 가장 큰 구조 차이는 다음과 같다.

- 배민·땡겨요는 한 메뉴 안에 여러 가격 variant를 둘 수 있다.
- 요기요·쿠팡이츠는 확인된 음식점 편집기 기준 메뉴 가격이 단일값이므로, 사이즈를 별도 메뉴 또는 필수 옵션으로 변환해야 한다.
- 땡겨요는 배달·포장·매장식사 가격을 한 가격행에 각각 보관한다.
- 쿠팡이츠는 배달과 포장의 메뉴·가격을 동일하게 운영하는 정책 제약이 있다.
- 배달특급은 `상품 원장 → 판매 메뉴 → 메뉴판`이 분리되어 있어, 화면에 보이는 중복을 곧바로 중복 상품으로 판단하면 안 된다.
- 네이버 주문은 일반 공개 API가 아니라 스마트플레이스 편집 또는 별도 푸드테크 연동 신청 경로다.

## 2. 판정과 증거 등급

### 2.1 투영 판정

| 코드 | 의미 | 자동 반영 정책 |
|---|---|---|
| `EXACT` | 기준 정보가 손실 없이 표현됨 | 자동 반영 가능 |
| `TRANSFORM` | 규칙으로 동일한 판매 의미를 만들 수 있음 | 변환 결과 미리보기 후 자동 반영 가능 |
| `LOSSY` | 일부 정보가 사라지거나 고객 표시가 달라짐 | 명시적 승인 전 차단 |
| `MANUAL` | 승인·서류·플랫폼 운영자 작업 등이 필요함 | 작업 안내만 생성 |
| `UNSUPPORTED` | 플랫폼이 해당 기능을 제공하지 않음 | 반영 대상에서 제외하고 이유 표시 |
| `UNVERIFIED` | 기능 유무 또는 서버 검증값을 확인하지 못함 | 자동 반영 차단 |

### 2.2 증거 등급

| 코드 | 의미 |
|---|---|
| `LIVE_UI` | 로그인된 실제 사장님 화면을 읽기 전용으로 확인 |
| `PUBLIC_SOURCE` | 현재 배포 중인 프런트엔드 JS/XML의 제한값 확인 |
| `OFFICIAL_HELP` | 플랫폼 공식 도움말·정책·가이드 확인 |
| `WRITE_VERIFIED` | 테스트 메뉴를 변경하고 재수집·원복까지 확인 |
| `OPERATING_DATA` | 실제 수집 데이터 구조에서 확인 |
| `USER_OBSERVED` | 운영 중 사용자가 직접 확인한 현상 |
| `UNVERIFIED` | 추정하지 않고 미확인으로 남긴 항목 |

`LIVE_UI`와 `PUBLIC_SOURCE`는 화면 동작을 강하게 뒷받침하지만, 최종 저장 시점에만 실행되는 서버 검증까지 증명하지는 않는다. 실제 저장을 하지 않은 항목은 `WRITE_VERIFIED`로 올리지 않는다.

| 쿠팡이츠 | 로그인된 전용 크롬 세션에서 메뉴·옵션 API 수집 | 기존 메뉴명·단일 가격 변경 검증 | 직접 자동 로그인 실패 시 전용 크롬 세션 재사용 | 기존 메뉴명, 단일 가격 변경 |

| 배달특급 | 로그인된 전용 크롬 스냅샷/API 수집 경로 | 어댑터가 명시적으로 읽기 전용 | PAYCO 스마트오더 세션 재사용 | 수집·노이즈 분류·비교만 가능 |
| 네이버 주문 | 전용 크롬 스냅샷/API 수집 골격만 존재 | 어댑터가 명시적으로 읽기 전용 | 현재 계정 연결 보류 | 공식 규칙 기반 사전 검증만 가능 |

주의: 현재 브라우저 스냅샷 수집기는 메뉴·가격·그룹·옵션 중심이다. 메뉴 설명, 원산지, 영양정보, 이미지 원본과 승인 상태까지 완전한 원장으로 수집한다고 간주하면 안 된다.

| 플랫폼 | 메뉴명 | 그룹 | 구성·설명 | 문자 제한 | 판정 |
|---|---|---|---|---|---|
| 배달의민족 | 최대 30자, 음식 메뉴 적합성 확인 단계 | 그룹명 25자, 그룹 설명 500자 | 구성 250자, 설명 500자 | 전체 허용 문자표는 미확인. 설명의 `!`가 서버 검증에서 거절된 운영 사례가 있어 사전 검증 필요 | 길이는 `EXACT`, 문자셋은 `UNVERIFIED` |
| 요기요 | 최대 70자 | 그룹 추가·수정·순서·숨김·삭제 | 설명 최대 500자 | 명시적 허용 문자표 미확인 | 길이는 `EXACT`, 문자셋은 `UNVERIFIED` |
| 쿠팡이츠 | 현재 화면에서 정확한 최대 길이 미확인 | 그룹을 먼저 만든 뒤 메뉴 생성 | 설명 최대 500자 | 금지 품목·금지 단어 검증, 외국어는 한국어 병기 권고 | 길이 `UNVERIFIED`, 금지어 `MANUAL` 가능 |
| 땡겨요 | 최대 50자 | 옵션 그룹명 30자. 메뉴 그룹명 제한값은 별도 확인 필요 | 구성 250자, 설명 500자 | 아래 허용 문자표 적용, 문자·숫자 없이 특수문자만 쓴 이름은 거절 | 확인 항목 `EXACT` |
| 배달특급 | 마스터 상품명 `simpleName` 최대 50자 | 분류명 50자, 분류코드 20자, 메뉴판 카테고리 간편명 `categorySimpleName` 50자 | 설명 입력란은 있으나 클라이언트 최대 길이·문자셋 미확인 | POS 메뉴코드 최대 20자, 허용 문자표 미확인 | 확인된 길이는 `EXACT`, 나머지는 `UNVERIFIED` |
| 네이버 주문 | 정확한 최대 길이 미확인 | `전체` 카테고리 메뉴는 주문에 노출되지 않음 | 맵기·추천·원산지·영양정보 별도 필드 | 한/영/중/일 문자, 숫자와 `-_():&![],.%+~@*^'/?²℃※<>` 허용. 이모지·그 외 문자는 저장 차단 | 문자셋 `EXACT`, 길이 `UNVERIFIED` |

### 땡겨요 허용 문자 세부

메뉴명·가격분류명·옵션그룹명·구성·설명에서 현재 소스가 허용하는 범위는 공백, 한글 자모/완성형, 영문, 숫자, CJK 한자와 다음 문자다.

```text
! @ $ ^ ` _ - | ? " ; ' : , . / ~ % & ( ) + { } [ ] ™ ®
```

옵션명 오류 메시지에는 `#`도 허용한다고 적혀 있지만 실제 검증 정규식에는 `#`가 없다. 자동화는 메시지가 아니라 실제 정규식에 맞춰 `#`를 금지해야 한다.

## 5. 가격·사이즈·채널 가격

| 플랫폼 | 한 메뉴의 가격 구조 | 행/라벨 제한 | 채널 가격 | 핵심 검증 | 기준 메뉴 투영 |
|---|---|---|---|---|---|
| 배달의민족 | 여러 가격 variant | 최대 20행, 라벨 20자 | 배달·매장·픽업 | 1~500,000원. 픽업 가격은 매장 가격이 있어야 하며 매장 가격보다 클 수 없음. 1,000원 미만 경고 | 동일 variant는 `EXACT`; 생성 화면에서 채널 필드가 숨겨져 생성 후 수정이 필요한 경우 `TRANSFORM` |
| 요기요 | 메뉴당 단일 가격 | variant 행 없음 | 메뉴 편집기에서 별도 포장가 미확인 | 사이즈는 별도 메뉴 또는 옵션으로 표현 | 별도 메뉴/필수 옵션으로 `TRANSFORM`, 고객 표시가 달라지면 `LOSSY` |
| 쿠팡이츠 | 메뉴당 단일 기본가 + 옵션 증액 | variant 행 없음 | 배달·포장 메뉴 구성과 가격을 동일하게 운영 | 필수 옵션의 추가금으로 표시가를 인위적으로 낮추면 정책 위험. 0원 필수 선택지 권장 | 사이즈 필수 옵션은 `TRANSFORM`; 채널별 가격 차이는 `UNSUPPORTED` |
| 땡겨요 | 여러 가격 variant | 최대 20행, 라벨 20자 | 각 행에 배달·포장·매장식사 가격 | 활성 서비스 가격 필수, 0원은 확인 경고, 0~500,000원 | 채널과 라벨이 보존되면 `EXACT` |
| 배달특급 | 상품 원장/판매 메뉴/메뉴판에 가격이 분산 | 마스터 상품 가격 입력은 최대 10자리 UI, 정확한 서버 상한 미확인 | 주문유형에 배달·포장 확인 | 숨김·종료 중복 행이 원장에 남을 수 있음 | 원장 ID와 판매 메뉴 ID를 먼저 연결해야 하며 그 전에는 `UNVERIFIED` |
| 네이버 주문 | 기본 가격 + 주문용 메뉴 옵션 | 정확한 행 한도 미확인 | 픽업 주문 중심, 별도 배달/매장 채널 가격 미확인 | 예약·주문 공용 수량형 메뉴 외 옵션은 주문에만 적용 | 옵션 변환은 `TRANSFORM`; 채널별 가격은 `UNVERIFIED` |

사이즈가 가격행인 플랫폼과 옵션인 플랫폼을 동일 객체로 덮어쓰면 안 된다. 기준 모델에는 `priceVariants[]`와 `optionGroups[]`를 둘 다 유지하고, `sizeSemantic`으로 사이즈 의미를 별도 표시한다.

| 배달의민족 | 메뉴당 최대 6장, 최소 1280×960, 최대 8960×6720, 4:3 편집 | JPG/PNG, 장당 최대 15MB | 검수. 대기·진행 중 수정 제한 | 4:3 원본 또는 안전 크롭 파생본 생성. 투명 여백·합성·중복·과도한 확대 등을 사전 경고 |
| 요기요 | 메뉴당 단일 이미지. 정확한 픽셀 규격은 현재 UI에서 미노출 | PNG/JPEG. 정확한 용량 상한 미확인 | 직접 등록 후 플랫폼 처리. 미등록 상태가 오래 지속되면 기본 이미지가 붙을 수 있고 그 이미지는 요기요 내부 전용 | 배민 원본에서 단일 대표 사진 선택. 크기·용량은 업로드 직전 UI 재탐색 없이는 `UNVERIFIED` |
| 쿠팡이츠 | 최대 3장, 최소 1280×960 | 라이브 업로더: JPG/JPEG/PNG/GIF, 장당 최대 15MB. 공식 권장: 1280×960, 300ppi, JPG/JPEG/PNG | 승인 심사, 반려 가능. 순서 변경은 즉시 반영 | 4:3 안전 파생본 생성. GIF는 UI 수용과 공식 권장 형식이 다르므로 자동 기본값에서 제외 |
| 땡겨요 | 1080×660 또는 660×660 | JPG/PNG, 최대 500KB | 땡겨요 제공 이미지는 즉시, 사장님 이미지는 최대 2주 승인. 승인 대기·타임세일 메뉴 수정/삭제 제한. 대표 메뉴 이미지는 삭제 불가 | 1080×660과 660×660 두 파생본을 미리 생성하고 500KB 이하 검증 |
| 배달특급 | 마스터 상품 등록 화면에 단일 파일 선택기 확인, 정확한 이미지 수·픽셀 규격 미확인 | `accept`·용량 제한이 클라이언트 입력에 표시되지 않음 | 마스터 상품 등록 단계에 포함 | `UNVERIFIED`, 자동 업로드 차단 |
| 네이버 주문 | 메뉴 이미지 규격 미확인. 프로모션 이미지는 별도 규격 | 프로모션: JPG/GIF/PNG/BMP/HEIF, 파일당 20MB, 한 번에 50MB | 저작권·초상권 준수, 프로모션 편집 정책 적용 | 메뉴와 프로모션 이미지를 다른 자산 타입으로 관리 |

이미지는 플랫폼별로 다시 압축한 파일만 저장하면 안 된다. 원본과 플랫폼별 파생본, 크롭 영역, 해시, 승인 상태, 반려 사유를 모두 보관해야 한다.

## 10. 플랫폼별 상세 투영 규칙

### 10.1 배달의민족

- 기준 레퍼런스 플랫폼으로 사용한다.
- 다중 사이즈는 우선 `priceVariants`로 보존한다.
- 필수 옵션 그룹에는 가능하면 0원 기본 선택지를 둔다.
- 신규 생성은 `메뉴 유형 → 메뉴명 검증 → 그룹 → 가격 → 이미지/설명/옵션` 4단계 흐름이다.
- 생성 화면과 기존 메뉴 상세 화면의 채널 가격 필드 노출이 다르므로, 채널 가격이 있으면 생성 후 상세 수정까지 하나의 트랜잭션처럼 계획한다.
- 이미지 검수 대기 중에는 같은 이미지를 재업로드하지 않는다.

### 10.2 요기요

- 배민 가격 variant를 그대로 보낼 수 없다.
- 고객에게 각 사이즈가 메뉴판에 독립 노출되어야 하면 `M`, `L`을 별도 메뉴로 만든다.
- 한 메뉴에서 사이즈를 고르게 하려면 필수 옵션 그룹으로 바꾸되, 메뉴 표시가격과 추가금 표시가 달라질 수 있음을 미리보기에서 경고한다.
- 플랫폼 기본 이미지는 외부 재사용 가능한 원본으로 간주하지 않는다.
- 현재 어댑터는 읽기 전용이므로 모든 쓰기는 차단한다.

### 10.3 쿠팡이츠

- 배달·포장 가격 차이를 보내지 않는다. 차이가 있으면 자동 반영 대상에서 제외한다.
- 사이즈는 필수 옵션 그룹으로 변환하는 것이 기본이다.
- 필수 옵션의 최저 추가금 때문에 메뉴 표시가격이 달라지지 않도록 0원 기본 옵션을 사용한다.
- 리뷰 이벤트는 일반 옵션 그룹에 섞지 않고 전용 이벤트 객체로 관리한다.
- 이미지 승인 요청과 텍스트 메뉴 저장을 서로 다른 작업으로 기록한다.

### 10.4 땡겨요

- `variant 라벨 + 배달/포장/매장식사 가격`을 모두 비교 키로 사용한다.
- 기존 메뉴 가격 변경은 현재 variant 개수, 라벨, 채널 집합이 기준 메뉴와 정확히 같을 때만 실행한다.
- 구조가 다르면 대표가격 하나로 모든 입력칸을 덮지 않고 검토 큐로 보낸다.
- 옵션명에서 `#`는 화면 메시지와 실제 정규식이 충돌하므로 금지한다.
- 이미지 업로드와 메뉴 텍스트 저장을 분리하고, 승인 대기 중 재시도하지 않는다.
- 스케줄은 메뉴 상태 덮어쓰기가 아니라 별도 엔터티로 보존한다.
- 현재 앱은 메뉴·다중 채널 가격과 옵션 그룹·항목·메뉴 연결을 함께 수집한다. 동명 또는
  누락 메뉴 연결은 임의로 합치지 않고 수집 완전성 오류로 기록한다.
- 옵션 그룹 목록은 `SMWME01T200.xml`의 `dma_optEdit`로 조회하며, 서버 조회 작업은
  `me/requestListOptionEdit`이다. 그룹 ID·이름·옵션 요약·옵션 수·연결 메뉴명을 돌려준다.
- 그룹별 옵션 원장은 `SMWME01T210.xml`의 `dma_optionList`로 조회하며, 서버 조회 작업은
  `me/requestListOtsOption`이다. 옵션 ID·이름·가격·판매/품절/숨김 상태·정렬순서와 그룹의
  필수 여부 및 최소·최대 선택 수를 함께 돌려준다.
- 메뉴 연결 화면 `SMWME01T120P08.xml`은 메뉴별 옵션 그룹 ID와 정렬순서를 보유한다.
  그룹 목록의 연결 메뉴명만으로는 동명 메뉴를 구분할 수 없으므로, 최종 수집기는 이 메뉴별
  연결 정보를 함께 읽어 플랫폼 메뉴 ID에 결합해야 한다.
- 옵션 쓰기는 목록 조회와 분리한다. 생성은 `me/requestRegOptionGrp`, 삭제는
  `me/requestDelOptionGrp`·`me/requestDelOption`을 사용하지만 라이브 저장 검증 전에는 호출하지 않는다.

### 10.5 배달특급

- 상품 원장 ID, 판매 메뉴 ID, 메뉴판 노출 ID를 각각 보존한다.
- 같은 이름의 `CLOSE` 행을 자동 삭제하거나 실제 판매 메뉴로 합치지 않는다.
- 대표 카테고리 복제와 진짜 중복 메뉴를 구분한다.
- 삭제 불가 비노출 행은 `legacy_noise`로 분류하되 원본을 지우지 않는다.
- 현재 쓰기 어댑터는 읽기 전용이다.

### 10.6 네이버 주문

- 로그인 확보 전에는 실제 화면 쓰기를 시도하지 않는다.
- 메뉴 옵션은 주문 전용이므로 예약 상품까지 함께 바꾸지 않는다.
- `전체` 카테고리는 주문 미노출이므로 실제 주문 카테고리를 반드시 지정한다.
- 프랜차이즈 본사·대행사 관리 여부를 먼저 검사한다.
- 공개 범용 API를 가정하지 않는다. 푸드테크 연동은 별도 신청·승인 기능으로 취급한다.
- 문자셋 검증은 저장 전에 로컬에서 수행한다.

## 12. 자동 반영 안전 게이트

아래 조건을 모두 통과하지 못하면 저장 버튼을 누르지 않는다.

1. 수집 완전성 증명: 전체 메뉴/옵션 응답인지, 단순 화면 일부인지 구분
2. 대상 식별: 이름이 아니라 플랫폼 고유 ID 우선
3. 구조 비교: 가격 variant 수·라벨·채널과 옵션 선택 규칙 비교
4. 제약 검증: 길이·문자셋·가격·이미지 규격을 로컬에서 검사
5. 변환 미리보기: 플랫폼에서 실제로 보일 메뉴/가격/추가금을 표시
6. 손실 차단: `LOSSY`, `MANUAL`, `UNVERIFIED`는 명시적 승인 없이는 실행하지 않음
7. 멱등성: 같은 요청을 반복해도 중복 메뉴·옵션 그룹을 만들지 않음
8. 저장 전 스냅샷: 원본 값과 API/DOM 증거 보관
9. 저장 후 재수집: 화면 성공 메시지가 아니라 재수집 값으로 성공 판정
10. 원복 정보: 생성·수정·숨김 각각의 보상 작업을 기록

## 13. 아직 남은 미확인 항목

빈칸을 없애기 위해 추정값을 넣지 않고 다음 항목은 명시적으로 `UNVERIFIED`로 고정했다.

- 배민 전체 허용 문자표, 옵션 그룹당 항목 수, 메뉴 노출 스케줄, 전용 리뷰 이벤트 구조
- 요기요 이미지 픽셀·용량 상한, 옵션 그룹·항목 수 상한, 옵션 텍스트 길이, 채널별 메뉴 가격
- 쿠팡이츠 메뉴명·옵션명 길이, 음식점 옵션 가격 단위, 그룹·항목 수 상한, 메뉴 스케줄
- 땡겨요 메뉴 그룹명 길이와 일부 삭제/복구 서버 정책
- 배달특급 설명 문자셋·서버 가격 상한·이미지 파일 규격·옵션 선택수와 원장 간 쓰기 순서
- 네이버 주문 메뉴·옵션·이미지의 정확한 길이·파일 규격과 현재 계정의 편집 권한

이 항목들은 실제 저장을 동반하는 통제 테스트 또는 플랫폼 공식 답변이 있어야만 `EXACT`로 승격한다.
