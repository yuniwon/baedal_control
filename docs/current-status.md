# Delivery Menu Sync 현재 구현 상태

- 기준일: 2026-04-13
- 기준 플랫폼: 배민
- 문서 목적: 지금 실제로 동작하는 기능, 제품 결정사항, 다음 작업 순서를 한 문서에서 확인하기 위함

## 1. 현재 한줄 요약

로컬 Electron 앱이 실행되고, `계정 저장 -> 메뉴 수집 -> 메뉴 관리 -> 매핑 검토 -> 반영 미리보기 -> 실행 기록` 흐름이 이어진다.  
현재 운영 검증과 화면 기준은 배민 중심으로 맞춰져 있다.

## 2. 지금 되는 것

### 2.1 앱 기본 구조

- Windows 로컬 Electron 앱 실행
- SQLite 기반 로컬 데이터 저장
- preload 브리지로 렌더러/메인 프로세스 분리
- React 기반 화면: 대시보드, 메뉴 관리, 옵션 관리, 매핑 검토, 계정 연결, 실행 기록
- 앱 이름을 `delivery-menu-sync`로 고정해서 개발 실행 / 직접 Electron 실행 / 빌드 실행이 모두 같은 `userData` 경로를 사용

### 2.2 계정 연결

- 배민 / 쿠팡이츠 / 땡겨요 계정 입력 및 저장
- 자격 증명은 Electron `safeStorage`로 암호화 후 `credentials.json`에 저장
- 저장 직후 해당 플랫폼의 메뉴 수집 시도
- 저장된 계정은 `다시 가져오기` 버튼으로 비밀번호 재입력 없이 재수집 가능
- 수집 성공 시 신규 연결 / 기존 연결 유지 여부를 구분한 메시지 표시
- 수집 과정의 화면, 텍스트, 필드 사용 여부를 `수집 검사` 패널에서 확인 가능
- 실사용 배민 계정으로 `다시 가져오기 -> 배민 메뉴 46개 재확인 -> 기존 연결 46개 유지` 흐름 확인

### 2.3 메뉴 수집과 저장

- 플랫폼 메뉴 카탈로그를 별도 저장
- 배민 옵션 탭의 옵션 그룹 카탈로그를 별도 저장
- 메뉴 매핑 레코드에 아래 정보 저장
  - 플랫폼 메뉴 ID
  - 플랫폼 메뉴명
  - 플랫폼 그룹명
  - 판매 상태
  - 가격 요약
  - 가게 연결 요약
  - 가게 연결 상태
- 같은 이름의 메뉴가 여러 개인 경우 중복 개수 계산
- 배민 메뉴 수집은 실제 계정 기준으로 로그인/셀프서비스 진입까지 확인됨
- 실제 로컬 DB 기준 최신 확인값
  - 기준 메뉴 `87`개
  - 배민 플랫폼 메뉴 `46`개
  - 배민 옵션 그룹 `15`개

### 2.3.1 배민 옵션 수집 범위

- 배민 `메뉴·옵션 관리 > 옵션` 탭 API 수집
- 옵션 그룹별 저장 정보
  - 옵션 그룹 ID / 이름
  - 최소 선택 수 / 최대 선택 수
  - 연결 메뉴 수
  - 옵션 항목 목록
    - 옵션 ID
    - 옵션명
    - 옵션 가격
    - 상태
    - 재판매 시각
  - 연결 메뉴 목록
    - 플랫폼 메뉴 ID
    - 플랫폼 메뉴명
    - 플랫폼 카테고리명
- 현재는 **읽기 전용 수집 + 표시**까지만 구현
- 옵션 수정/반영은 아직 범위 밖

### 2.4 메뉴 관리

- 기준 메뉴명 / 가격 수정
- 관리 제외 / 다시 포함
- 플랫폼에 아직 연결되지 않은 메뉴 삭제
- 필터
  - 전체
  - 관리 대상
  - 관리 제외
  - 가게 연결 검토 필요
  - 원본 누락 의심
  - 플랫폼에 없음
  - 재등장
- 원본 정보 카드 표시
  - 플랫폼명
  - 메뉴명
  - 상태 태그
  - 그룹명
  - 가격 요약
  - 가게 연결 메모
  - 마지막 확인 시각
  - 옵션 그룹 개수
  - 옵션 그룹 요약
- 메뉴를 카테고리별로 묶어서 표시

### 2.4.1 플랫폼 원본 상태 추적

- 플랫폼 메뉴 / 옵션 그룹 카탈로그에 아래 상태 저장
  - `present`
  - `missing_suspected`
  - `absent_confirmed`
  - `resurfaced`
- `플랫폼에 없음`은 정상 수집 2회 연속 누락일 때만 확정
- 수집 중 사라진 원본은 매핑을 바로 삭제하지 않고 상태만 바꿔 추적
- 동기화 미리보기는 `source_absent`, `missing_suspected`, `absent_confirmed` 원본을 실행 대상으로 올리지 않음

### 2.5 카테고리 처리 규칙

- 앱에서 보여주는 대표 카테고리는 **배민 기준**
- 배민 그룹명이 있으면 그 값을 우선 사용
- 배민 그룹명이 없을 때만 다른 플랫폼 그룹명을 보조적으로 사용
- 끝까지 없으면 `미분류`

이 규칙은 현재 UI 단순화를 위한 결정이다.  
플랫폼별 카테고리가 실제로 다를 수 있다는 점은 이미 고려하고 있으며, 나중에 별도 매핑 구조로 분리할 예정이지만 지금은 배민 기준으로 계속 진행한다.

### 2.6 매핑 검토

- 기준 메뉴별 그룹 표시
- 플랫폼별 후보 검색
- 현재 연결 후보 하이라이트
- 잘못 연결된 매핑 즉시 해제
- 연결된 메뉴와 후보 메뉴 모두 상세 메타데이터 표시
- 아직 저장된 상세 정보가 없는 경우 빈 상태 분리 표시

### 2.7 반영 준비와 실행 기록

- 대시보드에서 실제 연결 상태를 읽어 `연결됨 / 연결 대기` 표시
- 대시보드 요약 카드에 `연결된 플랫폼 수`, `마지막 반영 결과`, `변경 예정 메뉴 수` 표시
- 대시보드에 `이번 가져오기 변경점` 요약 패널 추가
  - 최신 수집 1회 기준으로만 집계
  - 새 메뉴 / 누락 의심 메뉴 / 플랫폼에 없음 메뉴 / 누락 의심 옵션 / 재등장 항목 표시
- 대시보드에서 `반영 미리보기` 클릭 시 반영 미리보기 생성
- `missing_mapping`, `binding_review` 상태를 검토 필요로 분리 표시
- `source_missing_review` 상태를 별도 표시
- 내부적으로 `선택 항목만 실행` 경로가 추가되어 특정 메뉴 1건만 안전하게 반영 테스트 가능
- `선택 항목만 실행`도 **최신 미리보기 기준으로 다시 검증**
  - 현재 실행 가능한 항목만 통과
  - 이미 `검토 필요` 상태로 바뀐 항목은 실행하지 않고 `실행 가능 0건, 제외 N건`으로 반환
- 실행 후 요약 문구를 한국어로 저장
- 실행 기록 페이지에서 조회 가능
- 실행 기록에서 메뉴별 성공/실패, 적용 대상 값, 실제 오류 사유까지 확인 가능

### 2.7.1 옵션 관리

- `옵션 관리` 탭 추가
- `logicalOptionGroups` 기준으로 같은 구성의 옵션을 한 묶음으로 표시
- 기본 화면에서 내부 옵션 그룹 ID는 노출하지 않음
- 현재 필터
  - 전체
  - 통합 가능
  - 원본 누락 의심
  - 플랫폼에 없음
  - 재등장
- 카드에서 보여주는 정보
  - 플랫폼명
  - 옵션 묶음명
  - 선택 규칙
  - 옵션 수
  - 연결 메뉴 수
  - 원본 그룹 수
  - 샘플 옵션명
  - 원본 그룹별 연결 메뉴와 마지막 확인 시각
- 실제 저장 데이터 기준으로 `전체 15개 옵션 묶음`이 화면에 표시되는 것까지 직접 확인

### 2.8 배민 실제 반영 검증 현황

- 숨김 메뉴를 대상으로 실제 배민 셀프서비스에 로그인하고 메뉴 검색까지 반복 검증함
- 배민 메뉴 검색 후보 선택 로직 개선
  - `연결 가게 없음` 요약을 바인딩 라벨이 없는 후보로 해석
  - 가격 요약 비교 시 공백과 `·` 차이 무시
- 배민 이름 변경은 더 이상 단순 타임아웃으로 실패하지 않음
  - AI 메뉴명 검사 결과를 기다림
  - 거절되면 실제 안내 문구와 함께 실패 기록에 남김
  - 저장 PUT 응답이 실패하면 배민 서버 오류 메시지를 그대로 기록함
- 실제 검증 결과, 일부 숨김 레거시 메뉴는 이름 자체는 허용되어도 저장 PUT 단계에서 배민 서버가 아래 이유로 거절함
  - `EXTERNAL_API_ERROR_40045`
  - `금칙어 '!'은 입력할 수 없습니다.`

이 오류는 현재 우리가 바꾸려는 메뉴명 때문이 아니라, 배민 서버가 기존 메뉴의 다른 필드까지 함께 검증하면서 발생하는 것으로 보인다.  
즉, **메뉴명/가격만 수정하는 범위여도 특정 기존 메뉴는 설명 등 다른 필드 상태 때문에 저장이 막힐 수 있음**을 실제 운영 계정으로 확인했다.

추가로 실제 상세 화면 검증 결과, 숨김 메뉴 `포테이토골드`는 상세 패널 `설명` 문구에 `!`가 들어 있었다.  
현재 앱은 이름 변경 전 상세 패널의 `설명` 텍스트를 먼저 읽고, 금칙어가 있으면 서버 저장까지 가지 않고 아래 문구로 선제 차단한다.

- `기존 메뉴 설명에 금칙어 '!'가 있어 이름 변경 저장이 막힙니다.`

즉, 이제는 같은 유형의 레거시 숨김 메뉴를 테스트할 때도 불필요하게 배민 저장 PUT까지 밀어넣지 않는다.

추가로 2026-04-13 기준 수동 실행 검증에서 아래를 다시 확인했다.

- `npm run build` 후 `electron out/main/index.js` 직접 실행 가능
- 직접 실행한 창도 기존 운영 데이터 경로 `C:\Users\WON2\AppData\Roaming\delivery-menu-sync`를 그대로 사용
- 메뉴 관리 화면에서 `전체 87 / 관리 대상 46 / 관리 제외 41 / 플랫폼에 없음 0` 표시 확인
- 옵션 관리 화면에서 내부 옵션 그룹 ID 없이 실제 옵션 묶음 목록 표시 확인

## 3. 제품 결정사항

### 3.1 당장 유지할 결정

- 메뉴 기준 데이터는 앱 안에서 직접 수정
- 현재 범위는 메뉴명 + 가격
- 카테고리 표시 기준은 배민
- 플랫폼별 예외는 구조적으로 대비하되, UI는 가능한 단순하게 유지

### 3.2 아직 미해결이지만 방향이 정해진 것

- 플랫폼별 카테고리가 다를 수 있음
- 지금은 배민 기준으로 묶고, 추후 필요 시 `기준 카테고리`와 `플랫폼 카테고리 매핑`을 분리
- UI가 복잡해지지 않도록 불일치가 있을 때만 펼쳐서 조정하는 방향으로 진행

## 4. 현재 남아 있는 작업

### 4.1 우선순위 높음

- 배민 메뉴 수정 전 기존 메뉴 상세 필드 검증 범위 확장
  - 현재는 `설명`의 `!` 금칙어만 선제 차단
  - 다른 금칙어 문자나 다른 필드까지 확장 검토 필요
- 쿠팡이츠 / 땡겨요 실제 사장님 사이트 DOM 검증
- 카테고리 불일치 감지와 후속 UX 설계

### 4.2 현재 범위 밖

- 옵션 수정 / 옵션 반영
- 설명
- 이미지
- 다매장
- 배달특급 / 네이버주문 / 요기요

## 5. 최근 반영된 주요 UI 개선

- 메뉴 관리 테이블 열 폭 재조정
- 관리 버튼 / 가격 입력 폭 축소
- 원본 정보 카드 구조화
- 원본 정보 카드에서 내부 ID 숨김
- 원본 상태별 태그 / 마지막 확인 시각 표시
- 원본 정보 카드에 배민 옵션 그룹 요약 표시
- 매핑 검토 카드형 배치로 가독성 개선
- 현재 연결 후보 강조
- 카테고리 헤더와 개수 표시 추가
- 계정 연결 화면에서 저장 / 재수집 동작 분리
- 수집 검사 패널이 길어져도 계정 입력 영역이 무너지지 않도록 레이아웃 안정화

- 대시보드 최신 수집 변경점 패널 추가
- 옵션 관리 탭 추가
