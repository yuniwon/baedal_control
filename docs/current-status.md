# Delivery Menu Sync 현재 구현 상태

- 기준일: 2026-04-14
- 기준 플랫폼: 배민
- 문서 목적: 지금 실제로 동작하는 기능, 제품 결정사항, 다음 작업 순서를 한 문서에서 확인하기 위함

## 1. 현재 한줄 요약

로컬 Electron 앱이 실행되고, `계정 저장 -> 메뉴 수집 -> 메뉴 관리 -> 매핑 검토 -> 반영 미리보기 -> 실행 기록` 흐름이 이어진다.  
현재 운영 검증과 화면 기준은 배민 중심으로 맞춰져 있다.

## 2. 지금 되는 것

### 2.1 앱 기본 구조

- Windows 로컬 Electron 앱 실행
- SQLite 기반 로컬 데이터 저장
- preload 브리지로 렌더러/메인 프로세스 분리
- React 기반 화면: 대시보드, 메뉴 관리, 옵션 관리, 매핑 검토, 계정 연결, 실행 기록
- 좌측 내비게이션 1차 단순화
  - 기본 노출: `홈 / 메뉴 / 옵션 / 가져오기`
  - `매핑 검토 / 실행 기록`은 `고급 기능 보기`를 눌렀을 때만 표시
- 앱 이름을 `delivery-menu-sync`로 고정해서 개발 실행 / 직접 Electron 실행 / 빌드 실행이 모두 같은 `userData` 경로를 사용

### 2.2 계정 연결

- 배민 / 쿠팡이츠 / 땡겨요 계정 입력 및 저장
- 자격 증명은 Electron `safeStorage`로 암호화 후 `credentials.json`에 저장
- 저장 직후 해당 플랫폼의 메뉴 수집 시도
- 저장된 계정은 `다시 가져오기` 버튼으로 비밀번호 재입력 없이 재수집 가능
- 수집 성공 시 신규 연결 / 기존 연결 유지 여부를 구분한 메시지 표시
- 페이지를 벗어났다가 돌아와도 저장된 아이디 / 비밀번호와 연결 상태 유지
- 각 플랫폼 카드에 `마지막 가져오기 시각 / 완료 여부 / 수집 요약` 표시
- 수집 요약에 아래 추가 정보 표시
  - 옵션 그룹 수
  - 중복 메뉴 정리 건수
  - `현재 세션 읽기` 여부
- 가져오기 일부 실패 시 설정 화면에서 즉시 실패 상태와 마지막 실패 이유를 확인 가능
- 수집 과정의 화면, 텍스트, 필드 사용 여부를 `수집 검사` 패널에서 확인 가능
- 실사용 배민 계정으로 `다시 가져오기 -> 배민 메뉴 46개 재확인 -> 기존 연결 46개 유지` 흐름 확인

  - 설정 화면에서 전용 크롬 실행 가능

### 2.5 카테고리 처리 규칙

- 앱에서 보여주는 대표 카테고리는 **배민 기준**
- 배민 그룹명이 있으면 그 값을 우선 사용
- 배민 그룹명이 없을 때만 다른 플랫폼 그룹명을 보조적으로 사용
- 끝까지 없으면 `미분류`

이 규칙은 현재 UI 단순화를 위한 결정이다.  
플랫폼별 카테고리가 실제로 다를 수 있다는 점은 이미 고려하고 있으며, 나중에 별도 매핑 구조로 분리할 예정이지만 지금은 배민 기준으로 계속 진행한다.

## 3. 제품 결정사항

### 3.1 당장 유지할 결정

- 메뉴 기준 데이터는 앱 안에서 직접 수정
- 현재 범위는 메뉴명 + 가격
- 카테고리 표시 기준은 배민
- 플랫폼별 예외는 구조적으로 대비하되, UI는 가능한 단순하게 유지

### 3.2 아직 미해결이지만 방향이 정해진 것

- 플랫폼별 카테고리가 다를 수 있음
- 지금은 배민 기준으로 묶고, 추후 필요 시 `기준 카테고리`와 `플랫폼 카테고리 매핑`을 분리
- UI가 복잡해지지 않도록 불일치가 있을 때만 펼쳐서 조정하는 방향으로 진행

### 3.3 플랫폼 통합 구조 메모

- 메뉴는 `대표 메뉴`와 `추천/프로모션 노출`을 분리해서 본다.
  - 예: 같은 메뉴가 `추천메뉴`와 실제 카테고리에 동시에 노출될 수 있음
  - 실제 수정 대상은 `실카테고리 기준 메뉴 1개`로 정리하고, 추천 노출 여부는 보조 정보로 보존
- 옵션은 `옵션 그룹 -> 옵션 항목 -> 가격/상태` 3단 구조로 통합한다.
  - 그룹명만 저장하면 수정이 불가능하므로 항목명/항목가격/선택 규칙이 함께 있어야 함
- 플랫폼마다 카테고리/옵션명이 조금씩 달라도 앱 안에서는 `논리 메뉴`, `논리 옵션 그룹`, `논리 옵션 항목` 단위로 통합하고,
  - 플랫폼 원본 이름과 연결 범위는 원본 정보로 따로 남겨 비교 가능하게 유지한다.

## 7. 에이전트 운영 리포트

앱 내부 DB와 기존 preview 엔진을 그대로 사용하면서, 에이전트가 DB를 직접 뒤지지 않고 현재 상태를 읽을 수 있는 읽기 전용 CLI 리포트가 추가됐다.

같은 제안 DTO를 IPC와 preload를 통해 렌더러에도 연결해서, 대시보드 안에서도 `지금 할 일` 패널로 바로 볼 수 있다.

- `electron out/main/index.js --task=agent-report-overview`
- `electron out/main/index.js --task=agent-report-review-queue --limit=5`
- `electron out/main/index.js --task=agent-report-menu --menuId=<menuId> --limit=5`
- `electron out/main/index.js --task=agent-report-options --platformCode=baemin --limit=5`
- `electron out/main/index.js --task=agent-report-platform --platformCode=baemin --limit=5`
- `electron out/main/index.js --task=agent-plan-next-actions --limit=5`

현재 리포트에서 바로 읽을 수 있는 것:

- 전체 기준 메뉴 수 / 관리 대상 수 / dirty 수
- 플랫폼별 실행 가능 건수 / 검토 필요 건수
- 최신 import 이력과 최근 실패 패턴
- 특정 메뉴의 플랫폼 매핑, 가격 variant, 최근 실행 기록
- 옵션 묶음 현황과 shape conflict 상태
- 플랫폼별 최신 import 변경점과 현재 managed Chrome 탭 상태

실행 제안 레이어에서 바로 읽을 수 있는 것:

- 지금 바로 실행 가능한 동기화 후보
- 사람이 먼저 확인해야 하는 검토 큐 후보
- 옵션 구조 통합 후보와 shape conflict 후보
- 같은 옵션명으로 여러 구조가 잡힌 경우 displayName 기준으로 묶은 옵션 구조 검토 후보
- 최근 실패 기준으로 다시 살펴볼 플랫폼 단위 점검 후보
- 대시보드 `지금 할 일` 패널에서 CLI와 같은 우선순위 제안 목록
- 실행 가능 항목은 실제 변경 필드만 요약하고, 다중 가격 변경은 `가격 구조`로 표시
- `변경 예정` 미리보기 대화상자도 같은 공용 요약 규칙을 사용
- 긴 다중 가격 요약은 기본 상태에서 접어 두고, `상세 보기`로 전체 변경 전/후를 펼쳐 확인할 수 있음
