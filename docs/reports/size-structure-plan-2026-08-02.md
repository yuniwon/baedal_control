# 사이즈·세트·리뷰 구조 정리안

점검 기준: 2026-08-02, 마지막 완전 수집본 2026-07-28

## 결론

표준 피자 M/L은 배민·쿠팡이츠·땡겨요·배달특급에서 이미 필수 옵션으로 표현되어 있다. 요기요만 M/L을 별도 원본 메뉴로 보관한다. 패밀리(F)는 일반 M/L의 형제가 아니라 별도 상품 크기이며, 대부분 플랫폼에서 독립 메뉴로 존재한다.

## 실제 수집 구조

| 플랫폼 | 표준 피자 사이즈 | 적용 메뉴 수 | 패밀리 사이즈 | 비고 |
|---|---|---:|---|---|
| 배민 | `사이즈 선택`: 미디움 +0 / 라지 +4,000, 필수 1개 | 20 | 독립 메뉴 | 가격 variant 행은 현재 1개, 사이즈는 옵션으로 운영 |
| 쿠팡이츠 | `사이즈 선택`: 미디움 +0 / 라지 +4,000, 필수 1개 | 18 | 독립 메뉴 | 기본가 + 옵션 증액 구조 |
| 땡겨요 | `사이즈 변경`: 미디움 +0 / 라지 +4,000, 필수 1개 | 19 | 독립 메뉴 | 배달·포장·매장 가격 채널은 별도 비교 |
| 배달특급 | `사이즈 추가선택`: M +0 / L +4,000, 필수 1개 | 19 | `가격` 그룹의 F +0 또는 독립 메뉴 | `가격` 그룹명만으로 의미를 판단하면 안 됨 |
| 요기요 | M/L 별도 메뉴 ID | 20쌍 | 독립 F 메뉴 | 활성 19쌍은 이미 한 통합메뉴에 연결됨 |
| 네이버주문 | 수집 보류 | - | 미확인 | 자동 투영 차단 |

요기요의 M/L 20쌍 중 19쌍은 하나의 통합메뉴에 이미 연결되어 있다. 남은 `슈퍼불고기 피자 M/L（하프앤하프）`는 두 원본 모두 `숨김`이고 통합메뉴도 관리 제외 상태라 자동 병합하지 않는다.

## 통합 규칙

1. 통합메뉴에는 `M`, `L`, `F`를 가격 변형으로 보관한다.
2. 원본 플랫폼의 실제 구조는 삭제하거나 억지로 동일화하지 않는다.
3. 필수 사이즈 옵션이 이미 있으면 해당 옵션의 기본값과 추가금을 변형 가격에 연결한다.
4. 요기요처럼 별도 메뉴로 분리된 플랫폼은 같은 통합메뉴에 `M/L` 원본을 여러 개 연결한다.
5. 배달특급의 `가격` 그룹은 연결 메뉴와 옵션 서명을 함께 확인한다.
6. `세트`, `두판`, `반반 선택`, `피자 선택`은 사이즈 변형과 별도의 구성 엔터티로 유지한다.
7. `리뷰 이벤트`·`후기참여` 그룹은 일반 옵션이나 사이즈 옵션으로 병합하지 않는다.

## 자동화 적용 순서

```text
통합 가격 변형(M/L/F)
  -> 플랫폼 원본 구조 판정
  -> native price variant / 필수 사이즈 옵션 / 별도 메뉴 중 선택
  -> 변환 미리보기
  -> 플랫폼별 적용
  -> 재수집 후 가격·선택 규칙 검증
```

현재 자동 쓰기는 옵션 구조 생성·변경까지 검증되지 않았으므로, 기존 메뉴를 옵션 방식에서 native 가격행으로 일괄 변환하지 않는다. 먼저 읽기·변환 미리보기와 테스트 메뉴 1건을 검증한 뒤 신규 메뉴부터 적용한다.
